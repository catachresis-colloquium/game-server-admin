== Overview

*Game-server discovery, configuration management, and administration* — built
on Gossamer (linearly-typed webview shell) and backed by VeriSimDB. GSA aims
to remain game-neutral; the current 18-profile registry is a legacy
compatibility inventory, not a universal server contract.

GSA provides a set of protocol probes, a legacy registry of game profiles,
configuration extraction/editing paths, and a GUI. The current registry still
loads the existing `profiles/*.a2ml` corpus for compatibility; A2ML is retired
by the current standards and is not a format for new profiles. A draft,
versioned JSON profile/config validator now exists only as a fixture-tested
slice; it is not wired into the GUI, public ABI, deployment path, or a live
game adapter. See `docs/developer/GAME-PROFILE-CONTRACT.adoc` for the boundary
and open maintainer decisions.

*New in this version:* User-configurable server connections with support
for default servers and favorites list. See Configuration for details.

All panels are registered in the PanLL Clade system with inheritance. The
existing game-profile clades correspond to the legacy profile corpus; the
fixture-only JSON contract does not generate production profiles or clades.

== Quick Start

[source,bash]
----
# Start the VeriSimDB instance
just verisimdb-up

# Build and run the CLI
just run status              # system status, VeriSimDB health, loaded profiles
just run probe <host> [port] # fingerprint a game server (default port 27015)
just run profiles            # list all 18 supported game profiles

# Or build and launch the GUI
just build && just gui
----

== Game Profiles and the Compatibility Boundary

The runtime registry still loads the existing `+profiles/*.a2ml+` corpus.
Those files are a legacy dependency: do not create, restore, regenerate, or
extend A2ML profiles, and do not bulk-rewrite the existing corpus. The registry
has not yet been migrated to a new canonical profile format.

A draft JSON descriptor and field validator are available at
`+schemas/game-profile-draft-0.1.schema.json+` and
`+src/interface/ffi/src/profile_contract.zig+`. The SOP example under
`+fixtures/standard-operating-psychopathy/+` is synthetic design data, not a
live server contract. The validator is currently exercised only by Zig tests;
it is not connected to the production registry, C ABI, GUI, deployment actions,
or a real adapter. It cannot establish server reachability or operational
status.

Before a stable contract or migration, maintainers must decide the canonical
serialization/schema, versioning and ownership, the mapping for legacy
profiles, and any session-data authorization/retention/audit requirements.
See `+docs/developer/GAME-PROFILE-CONTRACT.adoc+` and the
`+docs/reports/quality/2026-10-18-game-profile-recon.adoc+` recon report.

== ABI/FFI Standard

* *ABI (Idris2):* `+src/interface/abi/+` — formal type specs with
dependent type proofs
* *FFI (Zig):* `+src/interface/ffi/+` — C-compatible implementation
* *Core (Ephapax):* `+src/core/+` — linear type enforcement for resource
safety

== VeriSimDB Integration

Each managed server is a VeriSimDB octad with all 8 modalities:

* *Graph:* server→game-profile, server→cluster edges
* *Vector:* config embedding for similarity search
* *Tensor:* performance metrics over time
* *Semantic:* game type, version, mods, status
* *Document:* existing legacy config representation (A2ML output; not a new canonical contract)
* *Temporal:* every config version with timestamp
* *Provenance:* who changed what, when, why (hash-chain)
* *Spatial:* datacenter geolocation

Dedicated instance on port 8090 with persistent storage and 15s drift
detection.

== Configuration

GSA now supports user-specific configuration through a Nickel (`+.ncl+`)
configuration file. This allows you to:

* Set a default server IP and port
* Maintain a list of favorite servers
* Customize UI preferences
* Configure connection settings

=== Initial Setup

To create a default configuration file:

[source,bash]
----
./gsa config init
----

This creates `+user-config.ncl+` from the template.

=== Configuration Commands

[source,bash]
----
# Show current configuration
./gsa config show

# Set default server
./gsa config set-default mc.example.com 25565

# Add a favorite server
./gsa config add-favorite "My Minecraft" mc.example.com 25565

# List favorite servers
./gsa config list-favorites
----

=== Configuration File

The configuration file (`+user-config.ncl+`) is *gitignored* to ensure
your server credentials remain private. See `+USER-CONFIG.md+` for
complete documentation.
