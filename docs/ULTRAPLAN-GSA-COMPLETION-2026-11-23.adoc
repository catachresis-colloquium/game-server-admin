This is an evidence-based completion programme, not a claim that GSA is already production-safe.
It differentiates code on +main+, proposed changes in open PRs, reported field
qualifications, and capabilities still to be verified. No host mutation,

historical phase inventories, not the end-to-end production outcome defined here.

== 0. Scope, baseline, and intended product

Repository: link:https://github.com/catachresis-colloquium/game-server-admin[game-server-admin].
Inspected +main+ at +9becd3781bd7cef45cce083b023e1ef7111f075c+
(2026-11-12), tree of 660 tracked blobs, and open PRs #118, #119, #120,
#121, #122, #123, #124, and draft #130 (observed 2026-11-23).
This audit used repository contents and the GitHub Actions/PR record; it
did not reproduce the build or exercise a live target.

*Intension.* GSA is an optional, game-neutral operator/control plane for
discovery, inspection, configuration, lifecycle orchestration, backup policy,
and fleet management of independently running dedicated game servers. Its
core value is an explicit, auditable, safe mapping from a requested
deployment instance to one observed target and one authorized operation.

*Extension.* The 18 existing profiles are a *legacy compatibility inventory*
and do not imply 18 qualified operational adapters. A game profile describes
game behavior/expectations, a deployment declaration identifies an actual
installation, a collector produces time-bounded observations, and a policy
decision may permit a *specific* action. The underlying game or service
remains runtime and simulation authority. No game's normal startup, game
rules, connection handling, or persistence may require GSA availability.

*In scope:* the CLI, Zig implementation and C ABI, Idris2 authority,
Gossamer/Ephapax/AffineScript interfaces, local and remote transports,
instance registry, game adapters, persistence, safety, security, CI/CD,
deployment, governance, release evidence, and interoperability boundaries.

*Out of scope:* making GSA the game server, relocating game authority into
GSA, new universal game-specific commands by inference, or automatic
destructive operations against live player data.

=== Aspect-oriented invariant threads

Every interface, adapter, executor, action, and future game must be tested
against these cross-cutting invariants rather than treating them as one-time
modules:

* A-01 Identity: an operation selects one explicit, globally unique immutable instance ID and binds the host/runtime object on the same registry snapshot. Profile ID is never sufficient to choose among installations.
* A-02 Independence: the game keeps running and retaining its save data when GSA, its GUI, SSH transport or VeriSimDB disappears.
* A-03 Authorized effect: declaration or configuration is never itself authorization; authentication, allowed operation, game-safety policy and current evidence each gate side effects.
* A-04 Structured uncertainty: separate requested/issued/observed/confirmed actions; after SSH loss, timeout or partial output, report indeterminate rather than asserting success or replaying a destructive action.
* A-05 Preservation: a backup is not declared good until a representative restore proves the relevant game invariants; SIGTERM success is not evidence of clean checkpointing.
* A-06 Privacy and provenance: minimize logs, keep secret references opaque, record who/what/why/when and source identity, establish retention/deletion and access rules before player/session data.
* A-07 Resource safety: bound calls, queues, logs, CPU/memory, concurrency, output and target-specific exclusions; cancel queued operations safely; run no unbounded script through user JSON.
* A-08 Compatibility: distinguish Idris2 ABI authority, Zig FFI implementation, portable profile/instance contracts, backend adaptors, UI representation and game-owned simulation/authoring contracts.

=== Open PR integration order and decisions

1. Establish G0 and compare +phase2-foundation+ to +main+ (and current parent SHAs). An open, mergeable PR is not proof that its branch is current or its tests ran on the required base.
2. Qualify #120 on a fresh branch targeting +main+, then #121 against the merged result. Protect host-specific identifiers and never apply operational deployment files blindly to a new host.
3. Review #119's *eligibility-only* layer and #118's *bounded dispatch* layer as independent changes. Do not promote either to a live executor simply because its tests pass. Check shared allocator, concurrency, cancellation and output bounds.
4. Rebase/retarget #122 after #121, then #123 after #122, and draft #130 after #123. #122 modifies a legacy CryoFall A2ML profile: examine the exact delta against the prohibition on extending retired A2ML, distinguish pure compatibility repair from new authoring, and seek owner ruling if ambiguous.
5. #124 is documentation-only and can be independently reviewed. Its Windows/.NET and client-asset constraints are not evidence of Linux/runtime qualification. Keep #130 draft until its operator-owned declaration, environment, and client-readiness scope are approved.
6. Keep #125 (Burble relay / IDApTIK) separate from the game-server authority: GSA should observe a declared relay/service instance, not manage the match simulation. #111's fleet requirement is not complete until #118 is integrated and verified.

Do not merge an open branch solely to remove the backlog. Each merge requires
formatting, ABI checks if touched, on-base CI, tests, documented applicability
and a checked post-merge SHA. Close issues only against verified acceptance.

== 6. Security and correctness blocking experiments

These are *planned tests*, not executed results. Start in a disposable
host/container, preserve a known-good baseline, and do not inject failure
into a live player server without separate scope approval.

[cols="1,2,3,3",options="header"]
|===
|Test |Injection / threat |Required outcome |Abort / recovery

|E-01 |Send a valid-looking raw FFI action with a forged host/container and irrelevant handle. |No side effect; exact-instance policy and operator authorization prevent target substitution. |Isolated fake executor records zero dispatch; stop test if live target is addressed.

|E-02 |Change registry observation between selection and command; simulate PID reuse or unit/container replacement. |Identity checked at issue time and after observation; stale proof fails closed, not "healthy". |Disable writes, reconcile against fresh collector state.

|E-03 |Cut SSH after remote issuance but before acknowledgment; retry same operation. |Report indeterminate effect; never blindly replay a destructive command; reconcile before retry. |Query actual service state via fresh channel; manual authorization for recovery.

|E-04 |Force timeout, huge stdout/stderr, stuck child, simultaneous stop/start on same host. |Bounded result size, deadline and concurrency; cancellation safe; no false success on truncated output. |Kill disposable child, restore known state, compare process and audit logs.

|E-05 |Stop during a game's active save, then backup and restore. |Detect unsafe checkpoint, mark backup unsupported/failure, no corrupted restore presented as success. |Operate only on disposable save clone; restore pristine baseline and validate checksum.

|E-06 |Disconnect VeriSimDB, GUI and/or GSA during active play. |Game stays online; read-only core degrades truthfully; no loss of game-state authority. |Reattach control plane, reconcile, test missed observation handling.

|E-07 |Malformed JSON, duplicate IDs, stale schema, invalid KYAML, injection strings, secret-bearing logs. |Fail-closed parse and authorization; redacted output; validation verdict names exact rule and scope. |No live side effects, sanitized failure record.
|===

Record timestamps, exact revisions, environment, expected vs actual,
test fixtures, checksums and command receipts. PONS, panic-attack and
Hypatia scans augment the above; they cannot substitute for behavioral
failure and restore tests.

== 7. Estate standards, architecture and cross-repository compatibility

* DEED: A2ML is retired for new material. Legacy +profiles/*.a2ml+ and panel
  clades are compatibility data, not permission to generate more A2ML. The
  authoritative DEED parser grammar is
  link:https://github.com/metadatastician/standards/blob/main/1-formats/deed/spec/abnf/deed.abnf[deed.abnf].
  Audit and migrate eligible governance/coordination material only by
  approved canonical rules. This plan itself is AsciiDoc, not a DEED replacement.
* K9: files with K9 SVC Nickel component meaning conform to
  link:https://github.com/metadatastician/standards/blob/main/1-formats/k9/spec/K9-CONTRACT-SPEC.adoc[K9 Component Contract Specification]
  and its Nickel contract; this dialect is *not* governed by a K9 ABNF.
  The separate YAML-like +coordination.k9+ dialect is governed by
  link:https://github.com/metadatastician/standards/blob/main/2-protocols/k9-coordination/spec/abnf/coordination-k9-grammar_v1.3.abnf[coordination ABNF v1.3]
  (2026-11-21 spec, optional worker +reach+). Audit each actual K9 file
  against its correct dialect and report both checks; do not assume a
  panel +config.k9.ncl+ is a coordination file.
* JSON: preserve I-JSON/JCS strictness and numeric exactness where the
  repository's +estate-compliance.yml+ requires it. Fixtures do not
  automatically become production contracts. Canonicalization must preserve
  documented semantics and expected tests.
* KYAML: apply the estate format rule to authored YAML and GitHub workflow
  files while retaining GitHub-required suffixes. Never replace rule-aware
  validation with a generic YAML parser's success.
* ABI/FFI: Idris2 is authoritative for wire signature, enums, layout and
  relevant resource proofs; Zig is implementation, with generated expectation
  files checked by CI. A claimed formal proof must name its theorem, scope,
  trusted assumptions, compiler/version and executable linkage.
* UI/game boundary: use existing Ephapax, AffineScript and Gossamer surfaces;
  avoid new TypeScript. Game logic remains in IDApTIK / other games.
  Burble is optional session/relay orchestration, not a surrogate authority
  for gameplay. UMS is a content/authoring consumer; game-specific policies
  belong to the game.
* Persistence: VeriSimDB supplies optional audit, historical and search
  modalities, not authoritative live process state and not a startup
  dependency. Distinguish runtime observations, declarations, user intentions
  and provenance records.
* Testing: tie proof obligations and CI evidence to
  +proven-tests-and-benches+, PONS, panic-attack, Hypatia and independent
  runtime tests; never convert scanner success or a test-count badge into a
  production assurance percentage.

== 8. Release and documentation contract

For every version, publish a capability matrix with columns
+feature+, +backend+, +game+, +tested environment+, +read/write mode+,
+evidence SHA+, +supported/partial/unsupported+, and +recovery/rollback+.
The release page and installation guide must reflect that matrix, not the
legacy count of 18 profiles.

Pre-release checklist:

* Version and artifact/ABI compatibility fixed; signed, reproducible build and SBOM/provenance inspected.
* All *applicable* required gates run and pass, including any standards/lockfile governance required by repository protection; failures with zero jobs are diagnosed.
* Clean-machine install, CLI and selected GUI smoke tests, one real declared instance and two same-profile instances tested.
* Authentication, authorization, target identity, timeout, failure reporting, log redaction and audit receipts verified against executable negative tests.
* Game-specific backup/restore evidence for every supported advertised backup mode; recovery and rollback rehearsed.
* User-facing onboarding, fleet safety defaults, threats/runbooks, accessibility and privacy/retention terms updated.
* Release canary and postflight monitored; rollback path available without changing game-state authority.

The historical
link:https://github.com/catachresis-colloquium/game-server-admin/blob/main/ROADMAP.adoc[ROADMAP.adoc]
should remain a record of earlier phases but link to this plan as the
current completion gate. +README.adoc+, +TEST-NEEDS.adoc+,
+docs/INDEX.adoc+ and the April deployment runbook require a truth pass
before P1 release.
